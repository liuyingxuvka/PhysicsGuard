## ADDED Requirements

### Requirement: Blueprint loading has summary affected and deep projections
Each blueprint-aware PhysicsGuard route SHALL declare three distinct conditional projections: a compact current summary for route selection and ordinary bounded use, an exact affected slice for targeted analysis or modification, and the full qualified blueprint only for whole-boundary, deep-modeling, interchange, or closure work. Each projection SHALL bind the same current logical blueprint fingerprint and MUST NOT become an independent authority.

#### Scenario: Ordinary route selection
- **WHEN** a request needs only route choice and no blueprint-sensitive claim or change
- **THEN** the selected skill loads the compact summary and capsule without loading the full blueprint or unrelated route references

#### Scenario: Targeted change has an affected slice
- **WHEN** an exact changed element and current affected projection are available
- **THEN** the selected route loads that slice plus required shared objects and leaves unrelated branches unloaded

#### Scenario: Whole-boundary claim is requested
- **WHEN** the user requests complete target understanding, broad closure, interchange qualification, or another whole-boundary result
- **THEN** the selected native owner loads the full current blueprint and all required exact provider and evidence identities

### Requirement: Blueprint reference loading is route-owned and conditional
Each of the ten route capsules SHALL declare its blueprint summary, affected-slice, impact, reverse-trace, or deep-blueprint trigger only when relevant to that route. Initial loading SHALL remain limited to the selected route's compact prompt and capsule, and selection of one route MUST NOT authorize eager loading of all ten skill prompts, all blueprint shards, or another route's private protocol.

#### Scenario: Signal mapping needs one interface path
- **WHEN** the selected signal route needs the source and target interface, unit conversion, and affected evidence bindings
- **THEN** it loads only that current slice and its own declared protocol

#### Scenario: Candidate blueprint is authored
- **WHEN** the candidate-model-blueprint route creates or materially revises the physical blueprint
- **THEN** it conditionally loads the complete native blueprint protocol and exact current target inventory before candidate qualification

#### Scenario: Route eagerly requests every blueprint artifact
- **WHEN** a compact entry or capsule makes all blueprint shards, impact traces, deep protocols, or all skill references unconditional
- **THEN** prompt-load validation blocks the route as over-broad

### Requirement: Missing or stale projection fails visibly
A requested blueprint summary or affected slice SHALL be accepted only when its source blueprint fingerprint, target revision, selected member identities, shared-object fingerprints, and projection recipe are exact current. Missing, stale, ambiguous, or foreign projections MUST fail visibly and SHALL NOT fall back to a full blueprint, source scan, another route, or prior cached summary.

#### Scenario: Affected slice belongs to an older blueprint
- **WHEN** the selected slice fingerprint names an older blueprint or relation set
- **THEN** the route blocks and requests a current projection from the native owner

#### Scenario: Compact summary is missing
- **WHEN** ordinary blueprint-aware use requires the current summary but none exists
- **THEN** the route reports the missing projection and does not silently load the full blueprint

### Requirement: Prompt budgets preserve deep reachability
Blueprint-aware prompt and projection changes SHALL retain the current compact-entry byte limit and maximum reference depth while keeping the canonical blueprint review, exact affected impact, reverse trace, native-depth receipt, model-miss, validation, and closure paths conditionally reachable. Token reduction MUST NOT remove a required native owner, evidence identity, gap, layer status, or claim boundary.

#### Scenario: Prompt becomes smaller by dropping blueprint gaps
- **WHEN** a contracted prompt or summary omits first-gap, deepest-layer, stale, unsupported, or unresolved semantics needed by its route
- **THEN** prompt-load and route-contract validation fail despite the lower byte count

#### Scenario: Deep route remains conditional
- **WHEN** ordinary use does not require model creation, affected analysis, reverse trace, or whole-boundary closure
- **THEN** deep blueprint references remain reachable but are not loaded
