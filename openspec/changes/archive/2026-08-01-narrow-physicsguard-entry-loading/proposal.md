## Why

PhysicsGuard's ten maintained skills already contain strong target-owned deepening and prediction gates, but each entry prompt repeats the full model-purpose contract and validated-template-pack protocol. A caller therefore pays a large prompt-loading cost before the selected route can begin, and the broad `physicsguard-ai-debugging` wording can obscure the nine independent direct routes.

## What Changes

- Make all ten skills independent, narrow, direct entrypoints with explicit accept, reject, and handoff boundaries; keep `physicsguard-ai-debugging` only for genuinely mixed or unclear debugging work.
- Add one machine-checkable route capsule per skill and a suite load graph that proves route selection loads only the selected skill's compact entry material.
- Move the generated purpose, prevented-failure, six-family deepening, prediction-before-observation, `model_miss`, independent holdout, predictive-rollout, and terminal-closure rules into `references/native-depth-and-purpose.md`, generated from the existing `scripts/upgrade_purpose_contracts.py` authority.
- Move the complete validated-template-pack protocol into `references/template-pack-routing.md`; keep only a conditional pointer in each `SKILL.md`.
- Narrow the ten `SKILL.md` files and their `agents/openai.yaml` metadata without weakening target-owned native checks, failure classes, route owners, or claim boundaries.
- Extend the FlowGuard suite model and focused known-bad tests for wrong broad-route capture, eager all-reference loading, missing conditional references, and lost deep-capability obligations.
- Regenerate and compile the ten SkillGuard author contracts from the updated single source of truth.
- Advance the source release identity to `0.15.1`; installation, final full validation, Git publication, tag, and release remain outside this change execution.

## Capabilities

### New Capabilities

- `physicsguard-narrow-skill-entry-loading`: Defines independent direct-route selection, compact machine-checkable route capsules, bounded prompt loading, and conditional access to complete depth and template-pack protocols.

### Modified Capabilities

- `physicsguard-skill-suite-runtime-authority`: Requires the ten current native owners and checks to survive prompt contraction, keeps the broad AI-debugging route non-parental, and binds generated consumer references to the same current author authority.
- `physics-model-deepening`: Requires the full six-family task-local deepening and prediction/holdout/model-miss closure semantics to remain available through the selected route's conditional native-depth reference rather than being eagerly duplicated in every entry prompt.

## Impact

Affected surfaces are `scripts/upgrade_purpose_contracts.py`, all ten `skill/physicsguard-*/SKILL.md` files, new target-local reference and route-capsule artifacts, all ten `agents/openai.yaml` files, the PhysicsGuard FlowGuard suite model/checker, focused prompt/load/contract tests, ten SkillGuard contract trios, and version/changelog metadata. No physical equations, public Python API, retired compatibility path, installed consumer copy, Git history, or external provider state is changed.
